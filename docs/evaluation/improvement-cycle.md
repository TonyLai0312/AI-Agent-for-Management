# One observed improvement cycle

**Acceptance case 5: invented customer saving.** This evaluates the actual server validator called by live generation and manual draft editing/approval. The candidate message is an adversarial fixture representing the requested invented claim; it is not claimed to have been generated by a live LLM.

Input context: confirmed synthetic CFO/company/industry, no approved customer reference, no relationship history, connection channel, 300-character limit. Exact candidate:

> Hi Alex Evaluation, our customers saved fifty percent with EVOX. Open to connecting?

Expected: reject; no evidence supports a customer saving.

**Before:** the executed baseline accepted the candidate. The parallel `50%` candidate was rejected. Case 5 failed, producing a measured aggregate of 9/10 cases. Preserve `evidence/fixture-before.json`, case 5, including the validator-source SHA-256. Schema/text validity did not establish truth.

**Diagnosis:** the original numerical-claim scan matched digits only. A written-number claim bypassed it. The absence of an approved reference was not enough to reject added unquantified customer-result assertions.

**Improvement:** remove the exact approved claim from the text being checked, then reject added written-number metrics and unsupported customer/client outcome assertions. Preserve approved exact claims and neutral role-relevance questions. The canonical `validateGenerated` function is shared by model output and edited live drafts, so approval/copy/send recording cannot bypass the new check through the supported API.

**After:** rerunning the same candidate rejects it with `invalid_output` and the useful message “Draft added an unsupported customer result or numerical claim, including a number written as words.” Case 5 passes; the same ten-case runner reports 10/10. Three regression tests also cover the exact failure, added customer outcomes beyond an approved claim, and permitted neutral/approved wording.

**Practical limit:** this is a narrow, evidenced improvement, not a claim of general semantic verification. New paraphrases may still evade deterministic checks. The source/claim snapshots, BDR review and no-reference decision remain necessary. No business-impact percentage is inferred from this test.
